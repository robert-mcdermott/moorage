How to install Moorage, run it, and deploy apps to it. This documentation describes Moorage 0.9.0; the design documents describe how it works inside and where it is going.

  • Getting started: from nothing to an app with a URL, a preview and a rollback, in ten minutes.
  • Concepts: apps, environments, releases, gates and roles, on one page.
  • The examples: complete apps, ready to deploy.

Deploying apps#

  • With git push: the production branch deploys, and the push shows the build
  • From a forge: connect a repository on GitHub, GitLab or Gitea, with a preview for each pull request
  • Go
  • Python, with uv
  • Node.js, with npm
  • Static sites
  • In containers: a Containerfile, or an image from a registry
  • Anything else: your own build, a script, an app that is already built

The commands you will use most:

CommandWhat it does
moor deploy [DIR]Builds and deploys the source in DIR; prints the app's URL
moor deploy --image REFRuns an image, pinned to its digest
moor git remoteAdds the app's git remote: git push moorage main deploys
moor keys addRegisters your SSH key, so that you can push over SSH
moor registry login HOSTKeeps a private container registry's credentials on the server
moor trustTrusts the server's CA on this machine
moor server doctorChecks the server and what it depends on, and says how to fix what it finds
moor appsLists the apps; create, info, move, rename and delete one
moor eventsShows what happened on the server; -f follows it
moor deploymentsLists an app's deployments; show and follow one
moor releasesLists an app's releases; show one, and diff two
moor rollback [vN]Serves an earlier release again, in a moment
moor environmentsLists an app's environments; create and delete one
moor previewsLists the previews of branches; create, pin, unpin and destroy one
moor promote --from ENVReleases what one environment runs to another, without building it again
moor lock, moor unlockStops deployments to an environment, and lets them go on
moor sleep, moor wakeStops an environment's instances until a request wakes it, and starts them
moor accessShows who can reach an environment; set changes it
moor shareMakes a link that lets someone reach an environment; list and revoke them
moor domainsLists an environment's own hostnames; add, verify and remove one
moor redeployBuilds the current release's source again, and rolls it out
moor psLists the app's instances: status, health, port, PID
moor logs [-f]Shows the app's output, and with --source its builds, requests and events; --grep, --since and --problems narrow it down
moor restart [PROCESS]Replaces the instances without downtime
moor run -- COMMANDRuns a command in the current release, and ends with its exit status
moor run -it -- /bin/shA terminal in the current release
moor filesWhat is in the data directory
moor metricsShows requests, response times, CPU and memory over a range
moor cronLists the cron jobs; run one now, runs and log show how they went
moor scale [PROCESS=N ...]Shows or changes how many instances of each process run
moor envLists and changes variables and secrets; reveal reads a secret
moor manifest explainShows how Moorage will build and run the app
moor server statusShows the server and its service
moor login [URL]Signs in to a server, approving it in a browser
moor whoamiShows who you are signed in as
moor passwordChanges your password
moor projectsLists your projects; create, show, set, add-member, remove-member and delete them
moor auditShows who did what, for administrators
moor tokensLists your API tokens; create and revoke them

An app is chosen with --app, $MOOR_APP, [app].name in the moorage.toml of the current directory, or the repository's moorage git remote.

How Moorage works, in brief#

  • The server is the moor binary, run as a service. It keeps its state in one SQLite database and one data directory, and answers every app's hostname (<app>.<domain>) itself.
  • A deploy uploads the app's source, or pushes it to the app's git repository on the server. The server works out how to build it, installs the toolchains it needs (checked against their published checksums) and builds it in the directory it will run from.
  • A release is a build with its variables. A new release takes over only once its instances answer their health checks; the old ones finish their requests first. moor rollback brings an earlier release back.
  • Each instance runs under a small supervisor of its own, which restarts it when it fails and keeps it running while the server restarts.
