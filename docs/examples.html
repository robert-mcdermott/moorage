Examples

Complete apps, small but realistic, each ready to deploy.

Complete apps, small but realistic, each ready to deploy with moor deploy from its directory. Each has a README that says what it shows and how to run it locally.

ExampleWhat it isWhat it shows
python-fastapiA task list: FastAPI, uvicorn and a web pageuv and uv.lock, SQLite in the data directory, migrations as the release command, a health check that reads the database
go-stdlibA link shortener, with only the standard libraryA build from go.mod alone, HOST and PORT, a graceful stop, data that two instances can share during a deploy
node-expressA live poll: an Express API and a Vite front endnpm ci, a build script, pruning, the start script, assets cached for good, variables from [env]
static-siteA team handbookClean URLs, a 404 page, headers, redirects that keep old links working
container-goA guestbook, in an image with one binary in itruntime = "dockerfile", a multi-stage Containerfile, a user that is not root, resource limits, a release command with no shell. Needs Podman or Docker on the server

To try them, install Moorage on your own computer (installing Moorage):

moor server init --preset local
moor server run

Then, in another terminal, from an example's directory:

moor deploy

The app is at http://<name>.localhost:8080: tasks, links, poll, handbook or guestbook. Chromium- and Firefox-based browsers open *.localhost addresses on their own; for curl, send the name as the Host header (curl -H 'Host: tasks.localhost' http://127.0.0.1:8080/).

testdata/apps has smaller apps, one per runtime, that Moorage's own tests deploy.
